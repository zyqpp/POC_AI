# Kolejność Pracy

## Etapy

1. Zabezpieczyć starą dokumentację w archiwum.
2. Zbudować aktywną strukturę dokumentacji od zera.
3. Uruchomić narzędzia ekstrakcji faktów z kodu.
4. Opisać system, moduły i uruchomienie.
5. Opisać architekturę i integracje.
6. Opisać model danych.
7. Opisać API i DTO.
8. Opisać UI i AOS dla wszystkich route'ów.
9. Opisać procesy end-to-end.
10. Opisać role, testy, ryzyka i rekomendacje.
11. Uruchomić walidację jakości dokumentacji.

## Reguła małych partii

Każda większa partia dokumentacji powinna być możliwa do sprawdzenia osobno przez `git diff`, walidator jakości oraz przegląd źródeł kodowych.
