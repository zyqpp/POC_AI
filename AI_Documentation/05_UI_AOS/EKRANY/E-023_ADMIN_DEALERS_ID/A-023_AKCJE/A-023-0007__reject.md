## Opis Akcji

Odrzucenie dealera przez administratora. Wymaga podania powodu (pole `rejectReason`). Akcja wywoływana z dialogu po kliknięciu "Reject" w dialogu potwierdzenia. Zmienia status dealera na `Rejected`. Backend waliduje: `Reason.NotEmpty().MaximumLength(400)`.

## Ślad Techniczny

| Warstwa | Artefakt | Status |
|---|---|---|
| Element UI | Przycisk "Reject" w dialogu (trigger: A-023-0002 `showRejectDialog.set(true)`) | `wniosek z analizy` |
| Metoda komponentu | `DealerDetailComponent.reject()` | `wniosek z analizy` |
| Serwis frontend | `AdminApiService.rejectDealer(dealerId, {reason: rejectReason})` | `wniosek z analizy` |
| Endpoint API | `PUT /identity/api/admin/dealers/{id}/reject` z body `{reason}` | `wniosek z analizy` |
| Komenda/zapytanie | `RejectDealerCommand` → `RejectDealerCommandHandler` | `wniosek z analizy` |
| Walidacje | `RejectDealerRequestValidator`: `Reason.NotEmpty().MaximumLength(400)` | `potwierdzone` |
| Skutek w bazie | `Users/DealerProfiles.Status = 'Rejected'`, zapis `RejectionReason` (szacowane) | `wniosek z analizy` |

## Przykład HTTP

```http
PUT /identity/api/admin/dealers/{id}/reject
Content-Type: application/json
Authorization: Bearer {token}

{
  "reason": "Nieprawidłowe dane rejestracyjne — GST number nie pasuje do danych GUS."
}

Response: 200 OK
```
